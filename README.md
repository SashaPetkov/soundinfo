Техническая документация: Акустический веб-модем (Stop-and-Wait ARQ)
1. Общее описание системы
Данный проект представляет собой программный акустический модем, реализованный на базе Web Audio API и JavaScript. Система обеспечивает полудуплексную текстовую связку между двумя устройствами (например, ПК и смартфон) через динамики и микрофоны.
Главный приоритет архитектуры — высокая надежность передачи данных в условиях акустических помех и реверберации помещения. Для исключения накопительной ошибки синхронизации часов (Clock Drift) используется протокол с подтверждением приема Stop-and-Wait ARQ.
2. Физический и канальный уровень
2.1 Частотная сетка (FSK)
Модуляция выполняется методом частой манипуляции (Frequency Shift Keying). Для передачи сигналов используются следующие несущие частоты:
Назначение	Частота	Источник	Направление
Бит 0	7000 Гц	Передатчик (ПК)	ПК →  Смартфон
Бит 1	9000 Гц	Передатчик (ПК)	ПК → Смартфон
Подтверждение (ACK)	6000 Гц	Приемник (Смартфон)	Смартфон →  ПК
2.2 Временные параметры (Timing)
    • PULSE_TIME (70 мс): Длительность тона передаваемого бита.
    • ACK_TIME (50 мс): Длительность тона служебного сигнала подтверждения.
    • ECHO_PAUSE (120 мс): Пауза между итерациями передачи для затухания акустического эха в помещении.
    • TIMEOUT_MS (700 мс): Окно ожидания ответа ACK. По истечении времени выполняется повторная отправка бита (до 5 попыток).
3. Структура кадра (Frame Format)
Каждый текстовый пакет формируется следующим образом:
    1. Заголовок длины (4 бита): Число передаваемых символов (от 1 до 10 в двоичном представлении, например 0100 = 4 символа).
    2. Полезная нагрузка (Payload): Символы текста в кодировке ASCII (по 8 бит на каждый символ).
Пример: Для передачи слова "HI" (2 символа):
    • Заголовок длины: 0010 (2)
    • Символ 'H': 01001000 (88)
    • Символ 'I': 01001001 (89)
    • Итоговый битовый поток: 0010 01001000 01001001 (всего 20 бит)
4. Алгоритм обработки сигналов (DSP)
Демодуляция и поиск тонов в сыром PCM-потоке выполняются с помощью алгоритма Гёрцеля (detectFrequency).
    • Преимущество: Вычисление мощности строго заданной частоты $f_{target}$ без необходимости расчета полного БПФ (FFT), что существенно снижает нагрузку на процессор.
    • Порог детектирования: Сигнал считается зарегистрированным, если амплитуда спектральной составляющей превышает порог 0.003.
5. Протокол взаимодействия (Stop-and-Wait ARQ)
Пошаговая логика передачи каждого бита:
Передатчик (ПК)                         Приемник (Смартфон)
     |                                          |
     | ----- Тон 7000 Гц / 9000 Гц (70 мс) ---->|
     |                                          |  (Определяет бит по алгоритму Гёрцеля)
     |                                          |  (Задержка 40 мс)
     | <------- Тон ACK 6000 Гц (50 мс) --------|
     |                                          |
  (Фиксация ACK)                                |
  (Задержка ECHO_PAUSE: 120 мс)       (Блокировка приема на ECHO_PAUSE)
     |                                          |
     | ------------ Следующий бит ------------->|
Защита от самопомех и акустического эха:
    1. Self-Acoustic Blindness на ПК: После излучения тона ПК не анализирует микрофон первые 60 мс, чтобы гарантированно не принять собственное эхо за ответ ACK.
    2. Self-Acoustic Blindness на Смартфоне: После излучения ACK приемник смартфона блокирует цикл обработки (isProcessingBit = true) на время ECHO_PAUSE (120 мс), предохраняя микрофон от ложных повторных срабатываний.
6. Описание структуры кода
6.1 index.html
Содержит пользовательский интерфейс приложения:
    • Поле ввода текста с ограничением до 10 символов.
    • Кнопку инициализации и отправки пакета (btnSend).
    • Кнопку активации прослушивания микрофона (btnListen).
    • Окно логирования событий (#log) для отображения процесса связи в реальном времени.
6.2 script.js
Модуль содержит всю управляющую и DSP-логику:
    • getAudioContext(): Инициализирует и возобновляет работу AudioContext с частотой дискретизации 44100 Гц.
    • detectFrequency(samples, targetFreq, sampleRate): Реализация алгоритма Гёрцеля для вычисления мощности целевого тона.
    • playTone(freq, durationSec): Генератор синусоидального тона заданной частоты и длительности через OscillatorNode.
    • btnSend.addEventListener(...): Модуль передатчика. Переводит текст в биты, отправляет их поочередно, обрабатывает квитанции ACK и таймауты.
    • btnListen.addEventListener(...): Модуль приемника. Выполняет непрерывный сканирующий анализ сигналов с микрофона, отправляет ACK и собирает incoming-биты.
    • decodeBits(payloadBits): Преобразует принятую битовую последовательность в ASCII-строку и выводит результат на экран.
